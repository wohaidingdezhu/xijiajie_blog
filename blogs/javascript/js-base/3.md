## call、apply 和 bind 的区别

`call` 和 `apply` 立即调用函数，并返回函数的结果；`bind` 返回一个待调用的新函数。

- `fn.call(context, a, b)`：参数逐个传入。
- `fn.apply(context, [a, b])`：参数通过数组或类数组对象传入。
- `fn.bind(context, a)`：预置 `this` 和部分参数，稍后再执行。

`this` 是否会被转换，取决于被调用函数：严格模式函数保留传入的值；非严格模式函数把 `null`、`undefined` 转成全局对象，并将其他基本类型包装成对象。箭头函数的 `this` 不受这些调用方法影响。参见 [MDN：call](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Function/call) 和 [apply](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Function/apply)。

## 借助 Reflect.apply 封装

这个版本利用原生调用能力封装接口，适合准确理解参数形式，不是从零实现 JavaScript 的调用机制。它不修改传入对象，也不会覆盖内置的 `call` 或 `apply`。

```js
function callFactory(fn, context, ...args) {
  if (typeof fn !== 'function') {
    throw new TypeError('fn 必须是函数');
  }
  return Reflect.apply(fn, context, args);
}

function applyFactory(fn, context, args) {
  if (typeof fn !== 'function') {
    throw new TypeError('fn 必须是函数');
  }
  // 原生 apply 把 null 和 undefined 当作没有参数。
  return Reflect.apply(fn, context, args == null ? [] : args);
}
```

`Reflect.apply` 接受数组或类数组对象，不能直接用字符串等基本类型作为参数列表。它也不能把 `class` 当成普通函数执行。

```js
function total(a, b) {
  return this.base + a + b;
}

const context = Object.freeze({ base: 10 });
console.log(callFactory(total, context, 2, 3)); // 15
console.log(applyFactory(total, context, { 0: 2, 1: 3, length: 2 })); // 15

function readThis() {
  'use strict';
  return this;
}
console.log(callFactory(readThis, 0)); // 0
console.log(callFactory(readThis, null)); // null
```

## 用临时属性理解 this

面试中常见的思路是：把函数临时放在对象上，通过 `receiver[key](...args)` 调用。这适合演示对象方法调用，但有明确限制。

```js
function callOnObject(fn, receiver, ...args) {
  if (typeof fn !== 'function') {
    throw new TypeError('fn 必须是函数');
  }
  if (receiver === null ||
      (typeof receiver !== 'object' && typeof receiver !== 'function')) {
    throw new TypeError('receiver 必须是可扩展的对象');
  }

  const key = Symbol('temporaryCall');
  Object.defineProperty(receiver, key, { value: fn, configurable: true });
  try {
    return receiver[key](...args);
  } finally {
    delete receiver[key];
  }
}
```

`Symbol` 避免覆盖对象原有的属性，`finally` 确保函数抛出异常时仍然清理临时属性。这里不需要 `eval`。

这个版本不能处理冻结或不可扩展的对象，也不能保留基本类型、`null` 和 `undefined` 的严格模式 `this`。代理对象还可能拦截属性操作，因此不能将它当成通用的原生 `call` 替代品。
